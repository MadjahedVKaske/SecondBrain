# Desk: архитектура и восстановление

## Что является источником истины

- Локальный Desk использует MySQL на `127.0.0.1:3307`; это единственный источник личных задач, привычек, работ и игрового прогресса на этом компьютере.
- Код интерфейса и API живёт в `public/desk/` и `public/api/desk/`. Схема находится в `public/api/desk/schema.sql`.
- Операционные сущности (`desk_tasks`, чек-листы, привычки, работы) остаются фактом. Игровой слой только читает их и пишет отдельные профиль, навыки, привязки и неизменяемые события XP.
- «Пульс дня» лежит отдельно в `game_daily_pulses`: он необязательный, не образует серию и не влияет на бонус 5/5.

## Принципы игры

1. Экспедиция поддерживает действие, а не давит: нет штрафов, обнуления серий или потери XP.
2. Ранг отражает субъективную цену квеста. Базовые награды: серый 5, зелёный 12, синий 25, фиолетовый 50, золотой 100 XP; у красного XP назначается явно.
3. Арка — долгий результат; недельный квест — измеримый отрезок; задача — конкретное действие; чек-лист — следующий шаг. Они не подменяют друг друга.
4. Награды начисляются только через `game_events` с уникальным ключом источника, поэтому повторный просмотр или редактирование не начисляет XP второй раз.

## План развития

### Уже работает

- Квестовое отображение задач и чек-листов, пять дейликов, дополнительные дейлики, вода с шагами, ранги и XP.
- Компактная страница «Сегодня», план-завтра, недельные ориентиры и журнал фактически внесённых часов.
- Навыки/королевства, кампания «Хроники Второго Мозга» и необязательный «Пульс дня».

### Ближайшая архитектурная очередь

1. **Арки.** Отдельная сущность долгой цели с видимым прогрессом, связями на недельные квесты и задачами. Никакого автоматического назначения по названию.
2. **Фокус-экспедиция.** Необязательная сессия с мягким началом/завершением, связью с задачей и автоматической записью фактического времени. Она не удваивает XP.
3. **Журнал капитана.** Недельная сводка из задач, работ и добровольных пульсов; только наблюдения и вопросы, не диагнозы и не оценка человека.
4. **Выбранные награды.** Каталог личных наград за заранее оговорённые вехи. Без случайного лута, витрин и давления.

Мультиплеер, лиги, социальные механики и внешняя монетизация — отдельный будущий продукт, не часть личного Desk, пока его цикл не доказан на практике.

## Git и резервные копии

Git хранит код, схему и инструкции. Он **не** хранит личные записи Desk, пароли или рабочие SQL-дампы: `.local/` и `.secrets/` намеренно исключены из репозитория.

Создать локальную резервную копию:

```powershell
pwsh -File scripts/desk_local_backup.ps1
```

Дамп появится в `.local/desk-backups/` с датой в имени и SHA-256 от штатного дампера. Его следует периодически копировать в личное зашифрованное хранилище отдельно от Git.

Восстановление всегда перезаписывает локальную БД. Скрипт сначала создаёт предвосстановительный дамп, принимает только файл из `.local/desk-backups/` и требует явный флаг:

```powershell
pwsh -File scripts/desk_local_restore.ps1 -InputPath .local/desk-backups/desk-YYYYMMDD-HHMMSS.sql -ConfirmRestore
```

## Новый компьютер

1. Забрать эту рабочую копию из Git.
2. Установить/скопировать локальный PHP и MySQL согласно проектным локальным инструкциям; восстановить `docker/desk-config.local.php` из защищённого личного хранилища. Дампер понимает и старый `.secrets/mysql.local.json`, и действующий локальный конфиг Desk.
3. Запустить MySQL: `pwsh -File scripts/mysql_local_start.ps1`.
4. Восстановить выбранный SQL-дамп явной командой выше.
5. Запустить Desk: `pwsh -File scripts/desk_local_start.ps1` и открыть `http://127.0.0.1:8080/desk/`.

Продакшен и локальная база не синхронизируются автоматически. Любой будущий перенос между ними — отдельная проверяемая миграция, а не часть запуска или резервного копирования.
